# Журнал работы с ИИ

Основа для раздела «Описание процесса». Время — МСК, 22.11.2026.

## Инструменты
- **Claude Code** (модель Claude Opus 5.5) — исследование, план, весь код, тесты, документация. Работал в терминале с доступом к папке проекта, браузеру (через Playwright) и поиску.
- **Скиллы для интерфейса**: `impeccable` (проверка на «шаблонность» и полировка), `web-design-guidelines` (правила веб-интерфейсов Vercel: доступность, фокус, формы).
- Не ИИ, но участвовали: pytest (37 автотестов), Playwright (скриншоты на 12 размерах экрана), python-клиент `caldav` (проверка календаря как настоящий телефон).

## Этапы и ключевые промпты

### 1. Исследование (≈1 ч)
> «Вот ТЗ. Посмотри, как выглядит ЛК в других учебных заведениях. Посмотри, какие сертификаты безопасности и методы авторизации требует сейчас государство. Я бы добавил интеграцию с календарём на Apple, Android и HarmonyOS. Календарь должен быть рабочим.»

> «Стиль нужен без нейрослопа, просто утилитарный, как у ВШЭ/ИТМО/МГТУ/ЦУ. Найди информацию о внешнем виде интерфейсов… найди брендбук… дизайнерские скиллы для Claude… особенно важно, чтобы открывалось на всех ноутбуках хорошо.»

Что сделал ИИ: сравнил кабинеты ВШЭ (по скриншотам), ИТМО, МГТУ им. Баумана, ЦУ; нашёл требования 149-ФЗ (способы входа), 199-ФЗ (штрафы с 07.07.2026), приказа ФСТЭК № 117 (MFA), 152-ФЗ (локализация, согласие); выяснил, что в HarmonyOS NEXT нет подписки на календарь по ссылке, но есть «Добавить CalDAV-календарь» — отсюда решение писать собственный CalDAV-сервер.

Неудачи и как обошли:
- Сайт вуза отдаёт роботам JS-заглушку — страницы и PDF-положения открыты через управляемый браузер (Playwright) в контексте реальной страницы.
- Сервис распознавания капч не понадобился (на балансе не хватало средств) — браузер прошёл проверку сам.

### 2. Уточнение учебной системы (≈20 мин)
> «Только уточни, как у МГИМО устроена учебная программа: у ВШЭ есть веса, там их может не быть. Аналогично с системой зачётов и т. п.»

ИИ нашёл и прочитал официальные положения о рейтинговой системе: Р = 0,4·Б1 + 0,5·Б2 + 0,1·Б3 (текущий контроль — три среза + премия до 10; экзамен/зачёт; социальные характеристики), правило 70% для автоматического зачёта, потолок 69% для «традиционного» зачёта, штрафы за пересдачи (−10/−20), шкала A–F, скидки договорникам за рейтинг ≥ 90 и ≥ 95. Всё это стало модулем `grading.py` и 9 тестами.
Вывод в интерфейсе: «сколько нужно на экзамене, чтобы получить A» и предупреждение «ниже 70% — автоматического зачёта не будет».

### 3. План (≈15 мин)
ИИ составил план с порядком «сначала бэкенд, потом фронтенд», контрольными точками по времени и матрицей экранов (360×640 … 1920×1080, включая ноутбуки 1280×720 и 1366×768 с масштабом 150/125%). План утверждён человеком.

### 4. Бэкенд (≈2 ч)
Промпт-правила для ИИ зафиксированы в `CLAUDE.md` (только вымышленные данные, без логотипа, секреты только в окружении, чужое → 404, тест на каждое изменение API).
Порядок: схема базы → демо-данные → вход и сеансы → API студента → API сотрудника → календари → PDF справок → тесты.

Ошибки ИИ, пойманные тестами или проверкой:
| Ошибка | Как нашли | Исправление |
|---|---|---|
| Сравнение `integer[] && smallint[]` в PostgreSQL | падение заполнения базы | явное приведение `::int[]` |
| Поле модели `date: date | None` перекрыло тип | падение при запуске | поле переименовано в `day` |
| Русское имя файла в заголовке ответа (latin-1) | тест скачивания справки | `filename*=UTF-8''…` по RFC 6266 |
| Справку можно было закрыть, минуя «Готова» | тест недопустимого перехода | строгая схема переходов, отдельная для вопросов |
| «Дана Соколова Анна…» — без склонения ФИО | просмотр PDF глазами | формулировка, не требующая склонения |
| Водяной знак вылезал за край листа | просмотр PDF | уменьшен кегль |
| Поиск без учёта регистра не работал для кириллицы | ручная проверка | база пересоздана с ICU-локалью `ru` |
| Повтор кода 2FA в тестах (защита сработала на самих тестах) | падение фикстуры | фикстура сбрасывает последний шаг TOTP |

### 5. Фронтенд (≈1,5 ч)
Правила стиля из промпта («утилитарно, как у ВШЭ/ИТМО/МГТУ/ЦУ, без нейрослопа») ИИ перевёл в токены: тёмно-синий каркас, светлый рабочий фон, красный только для важного, шрифт Onest (OFL, хранится у себя), иконки Lucide. Перед вёрсткой прочитаны правила скилла `impeccable` (режим Operate: интерфейс-инструмент, а не лендинг; запрет градиентного текста, «стекла», надзаголовков, карточек-заглушек) и правила `web-design-guidelines`.
Фирменный приём — расписание в ритме печатного: слева колонка «время · пара», справа занятие; текущая пара выделена тёмной ячейкой, переносы — «было → стало» с причиной.

Проверка — скриптом Playwright: 6 страниц × 8 размеров экрана (360×640, 412×915, 768×1024, 1024×768, 1280×720, 1440×900, 1536×864, 1920×1080) — 48 снимков, горизонтальной прокрутки и ошибок JS нет. Сквозной сценарий через интерфейс: вход по форме → заявка → вход сотрудника с 2FA → изоляция факультетов.

Что исправлено после просмотра снимков:
| Замечание | Исправление |
|---|---|
| Номер заявки «З-2026-…» читался как «3-2026» — буква З похожа на цифру | номер без буквы, в интерфейсе «№ 2026-00001» |
| «Перенесено с среда, 25 ноября» — неграмотно | «Четверг, 26 ноября, 16:00: перенесено (было: среда, 25 ноября, 12:10)» |
| Вопрос в деканат получал статус «Выдана» | статусы зависят от типа: «Ответ дан», «Исполнена» |
| «ауд. Спорткомплекс» | префикс «ауд.» только у номеров аудиторий |
| Мелкие шрифты Vite вшивались как data: — их блокировала строгая CSP | отключено встраивание ресурсов |
| В воскресенье расписание открывалось на прошедшей неделе | по воскресеньям — следующая неделя |
| Готовая справка помечалась «просрочена» | «готова» не считается просрочкой |
| Строка уведомления реагировала на клик как кнопка (недоступно с клавиатуры) | явные кнопки «Открыть» и «Отметить прочитанным» |

### 6. Аудит и выкладка
Независимый агент-проверяющий (без контекста разработки) нашёл 8 проблем — от «заморозки» сервера серией запросов к CalDAV до блокировки чужого аккаунта попытками с трёх адресов; все воспроизведены и исправлены (таблица в `docs/SECURITY.md`).

Хостинг — Amvera (Москва): приложение из Dockerfile, управляемый PostgreSQL 17. Человек создал проекты и выдал ключ API хостинга; переменные окружения (секреты — только там), перезапуски и чтение статусов ИИ делал через API сам.
Что всплыло только на боевом стенде:
| Проблема | Как нашли | Исправление |
|---|---|---|
| Секреты, загруженные пачкой, сохранились пустыми — приложение не стартовало | лог запуска | секреты заданы по одному |
| Прокси хостинга пропускал подставленный `X-Forwarded-For` | вход с подменённым заголовком показал чужой адрес в истории | адрес — только самый правый публичный от внутреннего прокси |
| База хостинга с локалью C — поиск без учёта регистра не находил кириллицу | проверка на базе с локалью C | явная ICU-сортировка в запросах |

Проверено на стенде: вход, cookie `HttpOnly`/`Secure`/`SameSite=Strict`, CSP и HSTS, лента ICS (192 события), CalDAV настоящим клиентом через прокси хостинга (13 событий на неделю, запись — 403). Доступность без VPN — с узлов check-host в Москве и Санкт-Петербурге: 200 за 0,1 с.
