# Вход и защита данных

Простыми словами: чужое не откроется, пароли не хранятся, ключей нет ни в коде, ни в браузере. Ниже — как именно и чем это проверено.

## 1. Вход
| Что | Как сделано | Зачем |
|---|---|---|
| Логин и пароль | Пароль хранится только как хэш **Argon2id** (победитель конкурса Password Hashing Competition, рекомендация OWASP). | Даже при утечке базы пароли не восстановить. |
| Ошибка входа | Один и тот же ответ «Неверный логин или пароль» для несуществующего логина и неверного пароля; для несуществующего логина всё равно считается фиктивный хэш. | Нельзя узнать, какие логины существуют, ни по тексту, ни по времени ответа. |
| Перебор пароля | После **5 ошибок** вход для пары «логин + адрес» закрывается на **15 минут** (атомарно в базе, без гонок). Дополнительно — лимиты на адрес (30 ошибок / 10 мин; IPv6 — на сеть /64) и на логин со всех адресов (60 / 10 мин). Лимит на логин не действует на устройство, с которого владелец уже входил. | Перебор невозможен, а чужие попытки не запирают хозяина на его телефоне или ноутбуке. |
| Новый пароль | Проверка надёжности: оценка zxcvbn, словарь частых паролей, русские слова в латинской раскладке («ghbdtn» = «привет»), совпадение с логином и ФИО. | Слабые пароли не принимаются. |
| Сотрудник деканата | **Обязательная двухфакторная аутентификация** (TOTP, RFC 6238: Яндекс Ключ, Google Authenticator и т. п.). Повторно тот же код не принимается; ввод кода ограничен и на адрес, и на аккаунт (10 за 10 минут, 30 в сутки), после пяти ошибок владелец получает уведомление. Секрет TOTP хранится зашифрованным (AES-256-GCM). | Требование приказа ФСТЭК России № 117 (с 01.03.2026) о многофакторной аутентификации привилегированных пользователей. |
| Студент | 2FA по желанию (включается в разделе «Безопасность»). | |

### Сеанс
- Cookie сеанса: `HttpOnly` (недоступна скриптам), `Secure` (только HTTPS), `SameSite=Strict` (не уходит с чужих сайтов). Никаких токенов в localStorage.
- **Ключ сеанса меняется каждые 30 минут.** Если кто-то предъявит уже заменённый ключ (например, скопированную cookie), сеанс завершается целиком, а владелец получает уведомление «…ключ доступа использовали повторно — похоже на кражу cookie».
- Устройство запоминается отдельной cookie. Если cookie сеанса всплыла на другом устройстве, продолжить там можно только после ввода пароля, а владельцу приходит уведомление. Вход с нового устройства отмечается в истории, в «Безопасности» видны все сеансы (браузер, система, адрес, время) — любой можно завершить.
- Опасные действия (пароль приложения для календаря, смена пароля, отключение 2FA) требуют **повторного ввода пароля** — окно 10 минут.
- Срок сеанса без активности выбирает сам пользователь: 7 / 30 / 90 / 180 дней.
- Смена пароля завершает все остальные сеансы и отзывает ссылки календаря и пароли приложений — всё, что мог выпустить тот, кто знал старый пароль.
- **Общие демо-аккаунты для жюри**: нельзя сменить пароль и 2FA, завершать чужие сеансы и менять срок входа; адреса других проверяющих в истории скрыты (`198.51.x.x`). Так проверяющие не мешают друг другу.

### Госуслуги и требования закона о способах входа
- Часть 10 статьи 8 закона 149-ФЗ (в ред. 406-ФЗ) разрешает сайтам авторизацию через российский номер телефона, ЕСИА (Госуслуги), ЕБС или российские сервисы (VK ID, Яндекс ID, Сбер ID); иностранные системы входа запрещены, штрафы — ст. 13.55 КоАП (с 07.07.2026). Вход по логину и паролю на собственном сайте вуза этому не противоречит.
- В концепте работает вход по логину и паролю; кнопка «Войти через Госуслуги» показана неактивной: подключение ЕСИА делает вуз как оператор (регистрация информационной системы, OIDC, ГОСТ-подпись запросов). Код входа устроен так, что ЕСИА добавляется как ещё один способ входа к тому же сеансу.

## 2. Разделение данных
- Любой запрос к данным строится от пользователя из сеанса, а не от параметра в адресе. Идентификаторы в адресах — случайные (`/api/requests/u3CL0oRBE94h`), а не порядковые.
- Чужая запись отвечает **404 «не найдено»** — так же, как несуществующая: по ответу нельзя даже понять, что запись есть.
- Сотрудник видит заявки и группы **только своих факультетов**.
- Проверка — автотест `backend/tests/test_isolation.py`: программа обходит все маршруты API и подставляет идентификаторы чужих заявок, уведомлений, занятий и дедлайнов от имени другого студента и анонима. Ни один ответ не должен быть успешным.

## 3. Секреты
- Ключ шифрования, пароль базы, пароли демо-аккаунтов, секрет TOTP — только в переменных окружения сервера (`.env` вне репозитория, пример — `.env.example` без значений).
- Во фронтенде нет никаких ключей: он общается только со своим сервером, сеанс — в HttpOnly-cookie.
- Ссылка-подписка на календарь и пароли приложений для CalDAV — случайные секреты; в базе хранится только их SHA-256. Ссылку можно перевыпустить (старая сразу перестаёт работать), пароль приложения — отозвать. Основной пароль в календаре не используется.

## 4. Защита от типовых атак
- **CSRF**: изменяющие запросы принимаются только с того же сайта (проверка `Origin`) и с собственным заголовком `x-lk-request`, который чужая форма отправить не может; плюс `SameSite=Strict`.
- **XSS**: React экранирует вывод; строгая политика CSP (`default-src 'self'`, без inline-скриптов и сторонних доменов), шрифты и иконки хранятся у себя.
- **Встраивание в чужой сайт (clickjacking)**: `X-Frame-Options: DENY`, `frame-ancestors 'none'`.
- Прочие заголовки: `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, ответы API не кэшируются (`Cache-Control: no-store`).
- **SQL-инъекции**: только параметризованные запросы (psycopg).
- Лишние поля в запросах отклоняются (строгие модели), размеры полей ограничены.
- Журнал действий (`audit_log`) — кто что сделал, без паролей и секретов.

## 5. Справки
- PDF-справка содержит QR-код со ссылкой на страницу проверки `/verify/<код>`. Код — 128 бит случайности. Страница показывает только номер, вид документа, срок и маскированные инициалы («С******** А. Д.») — без персональных данных.
- В действующей системе справка подписывается усиленной квалифицированной электронной подписью (63-ФЗ); в концепте на ней пометка «образец».

## 6. Что потребуется для промышленной эксплуатации
- **152-ФЗ**: база с персональными данными граждан РФ — на территории РФ (ч. 5 ст. 18, с 01.07.2025 первичный сбор только в РФ); согласие на обработку — отдельным документом (с 01.09.2025); модель угроз и уровень защищённости по ПП РФ № 1119 и приказу ФСТЭК № 21.
- Если система связана с государственными информационными системами — меры по приказу ФСТЭК № 117 (МФА для администраторов уже реализована; критические уязвимости устраняются в срок до 24 часов).
- TLS: в концепте Let's Encrypt; в бою — дополнительно сертификат НУЦ Минцифры с ГОСТ-TLS для пользователей российских браузеров.
- Сертифицированные средства защиты (СЗИ ФСТЭК, СКЗИ ФСБ), резервное копирование, мониторинг, тест на проникновение.

## Чем проверено
`cd backend && python -m pytest -q tests` — 37 автотестов: вход и блокировка, ротация ключа и обнаружение кражи cookie, 2FA и запрет повтора кода, CSRF, флаги cookie, хэши паролей, обход всех маршрутов с чужими идентификаторами, права сотрудника по факультетам, полный путь заявки, календарь по ссылке и CalDAV настоящим клиентом.

## 5. Независимая проверка
Отдельный ИИ-агент без контекста разработки провёл аудит: обход всех маршрутов с чужими идентификаторами, сеансы и гонки, CSRF, CalDAV (XXE, «billion laughs», перебор), SQL-инъекции, path traversal, заголовки, секреты в истории git, service worker. Каждая находка воспроизведена на копии приложения и исправлена:

| Находка | Исправление |
|---|---|
| Запросы к CalDAV выполняли работу с базой в цикле событий — серия запросов могла «заморозить» сервер | работа с базой вынесена в пул потоков |
| Размер тела запроса не ограничен | 1 МБ на прокси и в приложении (заявленный размер проверяется до чтения), CalDAV — 256 КБ потоково |
| Аккаунт можно было запереть попытками с трёх адресов | лимит на логин не действует на знакомое устройство владельца |
| Сотрудник мог менять занятие общего потока, где есть группа чужого факультета | менять можно только занятие, все группы которого — его |
| Нет лимита на подбор кода 2FA на аккаунт | лимит на аккаунт + уведомление владельцу |
| Через общий демо-аккаунт видны адреса других проверяющих и их можно выкинуть | адреса скрыты, завершение чужих сеансов в демо отключено |
| Ссылка календаря продолжала работать после смены пароля и блокировки | отзывается при смене пароля, у заблокированных не отдаётся |
| Офлайн-копия кабинета на телефоне жила до явного выхода | не старше 12 часов; ответы, пришедшие после выхода, в кэш не пишутся |
