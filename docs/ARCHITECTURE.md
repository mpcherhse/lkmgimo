# Архитектура

```
 Телефон / ноутбук ──HTTPS──► Caddy (TLS, сжатие) ──► Приложение (FastAPI, N копий) ──► PostgreSQL 17
 Календарь iPhone/Google/Яндекс ──► /cal/<секрет>.ics          ▲
 Календарь HarmonyOS/macOS/DAVx⁵ ──► /dav/ (CalDAV, чтение)   │ сеансы, лимиты, блокировки — в базе,
                                                               │ поэтому копии приложения взаимозаменяемы
```

## Почему так
- **Одно приложение, один адрес.** Фронтенд (React, собранный Vite) отдаёт тот же сервер, что и API: нет CORS, cookie строго `SameSite=Strict`, CSP без сторонних доменов.
- **Сервер без состояния.** Всё состояние — в PostgreSQL (сеансы, лимиты частоты, блокировки входа). Нагрузку держат добавлением копий приложения за прокси (`docker compose up --scale app=4`) и, дальше, репликами чтения базы. В сессию и в начало семестра основная нагрузка — чтение расписания и оценок: это индексированные выборки по пользователю.
- **Календари не нагружают кабинет.** Телефоны опрашивают ленту раз в час, ответ кэшируется на 5 минут на стороне клиента; перенос занятия повышает `SEQUENCE` события, и календарь обновляет его, а не дублирует.
- **Минимум зависимостей.** Нет брокеров, кэшей и отдельных сервисов — их легко добавить, когда понадобится (уведомления push, очередь выгрузок из учётных систем).

## Модули бэкенда
| Файл | Что делает |
|---|---|
| `auth/core.py`, `auth/routes.py` | Вход, 2FA, сеансы с ротацией ключа, устройства, история входов, «Безопасность» |
| `routes_student.py` | Главная, профиль, расписание, сессия, успеваемость, заявки, уведомления, поиск |
| `routes_staff.py` | Очередь заявок факультета, смена статуса, ответы, перенос/отмена занятий, объявления |
| `grading.py` | Рейтинговая система: срезы, премия, экзамен/зачёт, правило 70%, пересдачи, рейтинг семестра, скидка |
| `calendar_feed.py` | Лента ICS, ссылки для iPhone/Google/Outlook, QR, пароли приложений, `.ics` для одного события |
| `caldav.py` | CalDAV только для чтения: обнаружение, PROPFIND, REPORT (query/multiget/sync), GET |
| `certificates.py` | PDF-справка с QR и публичная проверка подлинности |
| `notify.py` | Рассылка объявлений по факультету/курсу/группе и персональные уведомления |
| `seed.py` | Вымышленные данные: 3 студента разных факультетов и курсов, сотрудник, 4 семестра |

## Интеграция с учётными системами вуза (в бою)
Кабинет не заменяет учётные системы, а показывает их данные в одном месте. Источники подключаются по расписанию или событиям:
расписание — из системы составления расписания; оценки — из электронных ведомостей; контингент — из системы учёта студентов; документы — подписываются УКЭП в системе документооборота. В концепте эти данные лежат в той же базе (таблицы `lessons`, `grade_records`, `students`).
